Privacy policy

Last updated 1 November 2026

pflow.xyz is a free editor and toolset for building, running and checking models of systems, run by Matt York (stackdump). This page covers the website, its API and its MCP connector at https://pflow.xyz/mcp.

What we collect

  • Models you save. When you save a model, from the editor, the API or the pflow_save tool, it is stored under its content id (CID). Saved models are public: anyone with the CID can read them, and they can appear in the sitemap.
  • Who saved a model. A save records the account that made it. With GitHub that is your GitHub user id and username. With Google it is only Google's account id for you; we don't ask Google for your name or email address.
  • Editor sign-in. Signing in to the editor with GitHub asks GitHub for your profile, email address and permission to create gists. The access token goes to your browser; the server uses it to check who you are when you save and keeps only your user id and username.
  • Sign-in records. When an app such as Claude signs you in to the MCP connector, we keep a record of that sign-in (your account id, the app and an expiry date) so the app can stay signed in. It lasts at most 30 days after the app last refreshed it. While you sign in, our server also sets a cookie, pflow_mcp_auth, with a random value, for 10 minutes on the sign-in pages, so that a sign-in can only be finished in the browser that started it. We never see or store your GitHub or Google password.
  • Files in your account. If you use the editor's Save to my account, the file is stored on our server in a space only your signed-in account can reach. It is not public, and it stays until you delete it.
  • Drafting and assistant use. Each call to the editor's drafting or assistant features is logged with your GitHub user id and username, the prompt's version, the tokens used, the status and the time, so the daily limits hold. The text you type is not in this log. The assistant's automatic mode also counts each label it picks (day, mode, sentiment, confidence), with no user and no text.
  • Request logs. Our servers log each request's method, path, time and IP address, for running and debugging the service.
  • Analytics. The editor's home page and the composition views page (/compose.html) use Google Analytics to count visits, which sends Google the page address, the referring page, your IP address and browser details. A shared editor link carries its model in the address (after ?data=), so opening one sends that model to Google as part of the address. The composition page keeps its state in the part of the address after #; we have not checked whether Google's script reports that part, so don't put anything private in it. Google's tag also sets two cookies on pflow.xyz, _ga and _ga_ followed by our property id. They hold a random visitor id and details of your visit, last up to 400 days, and exist only after you have opened one of those two pages while analytics is on. Your browser sends them back to pflow.xyz with its requests, as it does any cookie, but nothing in our code reads them. The MCP connector and the other pages do not use Google Analytics.
  • Your browser's own storage. Some features keep data in your browser's local storage, session storage or IndexedDB. Loading the home page or the composition page stores none of it; each item appears when you use the feature that needs it. If you type in the home page's prompt and then sign in with GitHub, what you typed waits in this tab's session storage for the round trip and is deleted when it is read back; it goes to the assistant only then.
    • The editor, once you sign in with GitHub: your GitHub access token. It is also how the editor proves who you are: your browser sends it to our server whenever the editor checks your sign-in, saves, lists or deletes your models, or uses drafting or the assistant, and to GitHub if you create a gist.
    • The editor, as you work: the model you are editing (saved after each change), your display settings and panel layout, and, once you have entered the editor from the landing page or by a shared link, a flag that skips the landing page next time.
    • The editor's Describe box: the text you type, in session storage, which goes when the tab closes.
    • The editor's model library and notes, in IndexedDB, from your first analysis command on.
    • The composition page: the String view's level, if you change it.
    Apart from the token, as described, we don't receive any of this; it stays on your device until you clear your site data.

What we don't collect

Models you send to the MCP tools for checking, simulating or analysing are processed in memory and are not stored. Only pflow_save stores anything. We don't sell data, show ads or build profiles.

Who else sees it

  • GitHub or Google, when you choose to sign in with them, under their own privacy policies.
  • cdnjs (cdnjs.cloudflare.com): the editor loads its code-editor component from there each time it opens, with the same information as above. The editor falls back to a plain text box if it is blocked.
  • cdn.stackdump.com: the composition page and the editor's native commands download the engine from there, a server run by the author of pflow.xyz, with the same information as above. If it is unreachable the page uses its own copy.
  • GitHub gists, only if you press the editor's create-a-gist button while signed in: the model is posted to your GitHub account using your token.
  • Google Gemini, if you use the editor's drafting or assistant features: the text you type and the model you are working on are sent to Google's Gemini API to produce a reply.
  • Everyone, for models you save, because saved models are public.

How long we keep it

Saved models are kept so that their links keep working. Files in your account are kept until you delete them. Sign-in records expire as described above. Logs are kept only as long as needed to run and debug the service.

Your choices

You can use every tool except saving without signing in. To ask about your data, or to ask for a saved model or a sign-in record to be removed, open an issue at github.com/pflow-xyz/pflow-xyz/issues. You can also revoke pflow.xyz's access at any time in your GitHub or Google account settings.
