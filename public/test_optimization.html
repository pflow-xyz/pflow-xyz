Test Rate Optimization

This test page demonstrates the rate optimization features for Petri net transition rates. The optimization can find optimal rates to maximize token counts at target places using either continuous or binary optimization strategies.

Simple Example: Two Transitions Competing for Resources

Instructions:

  1. Click the hamburger menu (☰) in the top-left
  2. Select "🧮 Simulate (ODE)"
  3. Choose optimization mode:
    • Continuous [0,1]: Finds optimal real-valued rates without thresholding
    • Binary (0|1): Finds which transitions to fully enable (1) or disable (0)
  4. When Binary mode is selected, choose the optimization algorithm:
    • SPSA (recommended): Efficient stochastic optimization using only 2 evaluations per iteration
    • Gradient Ascent: Traditional finite-difference gradient method (N+1 evaluations per iteration)
  5. Click "Optimize Rates" button
  6. Select a target place (e.g., "Output A" or "Output B")
  7. Watch the optimization progress - iteration counts are automatically scaled based on problem complexity
  8. Click "Run Simulation" to see the result

Expected Behavior:

  • Continuous Mode:
    • Finds optimal real-valued rates between 0.0 and 1.0
    • No thresholding is applied - rates remain continuous
    • Works with both SPSA and Gradient Ascent algorithms
    • Iteration count scales with problem size (transitions + arcs)
  • Binary Mode:
    • Phase 1: Find continuous solution using selected algorithm (SPSA or Gradient Ascent)
    • Phase 2: Apply threshold at 0.5 (values > 0.5 → 1, else → 0)
    • Phase 3: Local bit-flip search to refine binary solution
    • SPSA is more efficient (2 evaluations/iter vs N+1 for gradient)
    • Both algorithms produce similar final results
  • Problem-Adaptive Iterations:
    • Iteration counts automatically scale based on number of transitions and arcs
    • SPSA: up to 300 iterations for complex problems
    • Gradient Ascent: up to 150 iterations for complex problems
    • Local search: up to 30 iterations based on number of transitions
  • If optimizing for "Output A", transition t1 should get a higher rate
  • If optimizing for "Output B", transition t2 should get a higher rate
